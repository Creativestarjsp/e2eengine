# Illustration Types and Responsive Behaviour

## Types

| Type | Use | Avoid |
| --- | --- | --- |
| Empty state | A central concept, one primary subject, few supporting elements; leave room for heading, description, and call to action | Text inside the artwork |
| Success | Positive visual language, a clear completion concept, subtle celebration, strong central focus | Excessive confetti or decoration |
| Error | Friendly communication, a simple failure concept, a sense that recovery is possible | Frightening imagery, aggressive warning visuals, heavy negativity |
| Onboarding | Characters, product interaction, visual storytelling, clear progression | Detail that competes with the instruction |
| Hero | Larger composition, several related elements, strong brand integration, more depth | Scaling up a small spot illustration |
| Feature | One core concept, supporting objects, compact composition | More than one idea per illustration |

## Sizes to hold up at

320 · 375 · 390 · 430 · 768 · 1024 · 1280 · 1440 px and wider.

No critical information in tiny details. When scaled down, the main concept must still be recognisable; check it at about 120 px wide.

## Mobile

- reduce complexity and the number of objects
- keep strong silhouettes and the essential information
- avoid consuming vertical space the content needs
- the call to action and content hierarchy stay dominant

If the illustration competes with the primary action, shrink it or remove it.

## Desktop

- use the available space; larger compositions where appropriate
- support hero layouts and asymmetrical compositions when useful
- avoid large empty areas and keep the content hierarchy clear

Do not simply scale a mobile illustration up to desktop; a hero needs its own composition.

## Performance

Keep spot illustrations small (the checker's default budget is 600 elements and 100 KB). Lazy-load large artwork below the fold. An illustration must never be the reason a view feels slow.
